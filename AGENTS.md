# Правила для ИИ-агентов

## Релизы приложения и ссылка на лендинге

- При каждом выпуске новой стабильной версии обязательно обновляй `site/src/release.js` вместе с `<Version>` в `Directory.Build.props`, до создания релизного коммита и сборки. Это относится и к ручным релизам без CI/CD.
- В `site/src/release.js` меняй `const version` на номер выпуска `X.Y.Z`. Ссылка на установщик, имя файла и ссылка на релиз вычисляются из этого номера. Все кнопки скачивания на лендинге должны использовать `latestRelease.downloadUrl`, а не отдельные адреса в компонентах или переводах.
- Номер версии приложения, версия в `site/src/release.js`, тег `vX.Y.Z` и имя установщика `BluetoothNotify-Setup-X.Y.Z-x64.exe` должны совпадать. Не переключай лендинг на черновик или предварительный релиз.
- Проверь лендинг командой `npm run build` из папки `site` и проверь кнопки скачивания на широком и узком экранах. Сохраняй локализацию всех девяти языков.
- Собирай установщик через `tools/Build-Installer.ps1`. Публикуй в GitHub Release и установщик, и созданный рядом `update.json`: он нужен резервной проверке обновлений в приложении.
- После публикации убедись, что релиз опубликован как стабильный, установщик загружен полностью, а `latestRelease.downloadUrl` соответствует его настоящему адресу. Обновление ссылки на лендинге является частью выпуска, а не отдельной необязательной задачей.
- Если пользователь просит выпуск без CI/CD, добавь `[skip ci]` в сообщение релизного коммита и аннотированного тега, собери локально и опубликуй релиз вручную. Не запускай и не отслеживай CI/CD, если пользователь просил его пропустить.
