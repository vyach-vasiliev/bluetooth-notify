# Техническое задание: Bluetooth Notify для Windows

## 1. Задача

Создать небольшое tray-приложение для Windows на C# и .NET 10. Приложение работает в фоне без обычного окна в панели задач, показывает рядом со значком в системном трее компактную тёмную панель со списком сопряжённых Bluetooth-устройств, их состоянием подключения и зарядом батареи, а также отправляет нативные уведомления Windows при подключении устройства.

Референс задаёт визуальное направление, но не должен копироваться пиксель в пиксель: тёмная карточка с закруглениями, шапка, кнопка обновления, информационная строка, карточки устройств, заряд и круглый индикатор подключения справа.

## 2. Зафиксированные решения и трактовки

1. Целевая платформа первой версии: Windows 11 22H2 или новее, x64.
2. UI: WPF на `net10.0-windows`, без консольного окна.
3. Публикация: framework-dependent. .NET runtime не включать в результат публикации. На компьютере пользователя должен быть установлен .NET Desktop Runtime 10 x64.
4. Приложение не занимается сопряжением устройств. Показывать уже известные/сопряжённые Windows Bluetooth-устройства.
5. Круглая галочка является только индикатором состояния. Зелёный круг с белой галочкой означает, что устройство сопряжено и сейчас активно/подключено. Тёмный круг без галочки означает, что сопряжённое устройство сейчас неактивно/не подключено. Пользователь не может переключать этот индикатор вручную.
6. Универсальное принудительное подключение/отключение гарнитур, мышей, клавиатур и других Bluetooth-устройств не входит в первую версию: Windows не предоставляет для всех классов устройств единый надёжный публичный API для такой операции. Не отключать устройства через Device Manager, не требовать прав администратора и не использовать недокументированные команды.
7. Панель обновляется сразу при открытии, затем раз в 1 секунду, пока она видима. Когда панель скрыта, секундный опрос прекратить; отслеживание событий подключения оставить событийным.
8. Основной язык UI первой версии — русский. Все пользовательские строки вынести в ресурсы, чтобы позднее можно было добавить английский без переписывания представлений.
9. Для установки использовать Inno Setup. В установщик не включать .NET runtime.

## 3. Пользовательский сценарий

1. После запуска приложение не показывает основное окно и создаёт значок Bluetooth в системном трее.
2. При наведении на значок и удержании указателя примерно 250–350 мс появляется панель возле значка.
3. Панель не должна мигать или постоянно открываться заново от повторяющихся `MouseMove`.
4. Пока указатель находится над значком или панелью, панель остаётся открытой. После ухода указателя из обеих областей она закрывается с задержкой примерно 350–500 мс.
5. Левый клик по значку переключает видимость панели и служит доступной альтернативой наведению.
6. Правый клик открывает нативное контекстное меню: «Открыть», «Обновить», «Выход».
7. Повторный запуск не создаёт второй экземпляр: существующий экземпляр получает команду показать панель.
8. При открытии сразу отображаются последние известные данные, запускается обновление и показывается неблокирующий индикатор загрузки.
9. При подключении сопряжённого устройства после запуска приложения Windows показывает нативное уведомление. При первоначальном чтении уже подключённых устройств уведомления не отправлять.

## 4. Состав и поведение панели

### 4.1. Окно

- Отдельное borderless tool window, `ShowInTaskbar=false`, без кнопок системного окна.
- Ориентир ширины: 420–460 DIP; высота адаптивная, максимум 620 DIP.
- Панель размещать относительно реального прямоугольника tray-значка и ограничивать рабочей областью его монитора.
- Учесть панель задач снизу, сверху, слева и справа, несколько мониторов и масштабирование 100/125/150/200%.
- Не уводить окно за границы экрана.
- При показе только от наведения не перехватывать фокус у текущего приложения. При клике по интерактивному элементу панель может активироваться.
- `Esc`, повторный клик по tray-значку, клик вне окна или уход указателя должны скрывать панель.
- Для Windows 11 использовать DWM-закругление и тень там, где это возможно; избегать `AllowsTransparency=true`, если оно ухудшает рендеринг текста или производительность.

### 4.2. Внешний вид

- Тёмный фон окна, чуть более светлые карточки, радиус углов 14–18 DIP.
- Основной текст почти белый, вторичный — серый, достаточный контраст.
- Не использовать emoji как UI-иконки.
- Поддержать клавиатурную навигацию, видимый focus state и системное масштабирование текста.
- Не кодировать размеры и цвета непосредственно в каждом контроле: вынести в ресурсы/токены темы.

### 4.3. Шапка

- Слева: Bluetooth-иконка в квадратной подложке.
- Заголовок: `Bluetooth Notify`.
- Подзаголовок: «Минимальный заряд подключённых устройств».
- Справа: кнопка принудительного обновления с иконкой refresh.
- Во время ручного обновления кнопка показывает состояние выполнения и временно защищена от повторного запуска; UI не блокируется.

### 4.4. Информационная строка

- Слева: «N устройств передают уровень заряда» с корректным склонением либо нейтральной формулировкой без склонения.
- Справа: «Обновлено HH:mm:ss».
- Время означает окончание последнего успешного цикла обновления.
- При частичной ошибке показывать ненавязчивый warning/tooltip, сохраняя доступные данные других устройств.

### 4.5. Список устройств

- Список прокручиваемый; приложение должно нормально работать с 0, 1 и десятками устройств.
- По умолчанию показывать все сопряжённые Bluetooth-устройства, а не случайные устройства поблизости.
- Одна физическая периферия, представленная Windows одновременно как Classic и LE, должна отображаться одной строкой. Для объединения использовать устойчивый идентификатор контейнера устройства, а адрес — только как fallback.
- Порядок: подключённые выше отключённых; внутри группы — по имени без учёта регистра.
- Для каждого устройства показать:
  - иконку типа;
  - пользовательское имя Windows;
  - состояние «Подключено»/«Не подключено»;
  - транспорт: `Bluetooth LE`, `Bluetooth Classic` или `Bluetooth LE + Classic`;
  - процент заряда и горизонтальную шкалу, если заряд доступен;
  - круглый read-only индикатор состояния справа.
- Если имя отсутствует, показывать «Bluetooth-устройство».
- Если заряд не поддерживается или временно не прочитан, показывать `—` и серую шкалу/состояние «Заряд недоступен», не выдавать 0%.
- Цвет заряда: 30–100% зелёный, 16–29% жёлтый, 0–15% красный, неизвестный — серый.
- Не удалять строку при временной ошибке чтения; отметить данные как устаревшие, если последнее успешное чтение старше 60 секунд.
- Пустое состояние: «Сопряжённые Bluetooth-устройства не найдены» и действие «Обновить».
- Состояние выключенного адаптера: «Bluetooth выключен или недоступен» без падения приложения.

### 4.6. Круглый индикатор подключения

- Индикатор только отображает вычисленное состояние устройства и не является кнопкой, checkbox или toggle.
- Активно: устройство сопряжено и Windows подтверждает текущее подключение; показать зелёный круг и белую галочку.
- Неактивно: устройство сопряжено, но сейчас не подключено; показать тёмно-серый круг без галочки, с различимой границей.
- Не считать устройство активным только потому, что оно сопряжено: состояние должно основываться на актуальном `IsConnected`/эквивалентном документированном признаке Windows.
- Изменение индикатора происходит автоматически при событии watcher или обновлении данных.
- Визуальный круг около 20–22 DIP; зарезервированная область не менее 32×32 DIP для ровного выравнивания строк.
- Не менять состояние по клику, нажатию `Space`/`Enter` или касанию. У индикатора не должно быть hover/pressed-вида, создающего впечатление интерактивности.
- Доступность: сообщать имя «Состояние устройства {имя}» и значение «Подключено»/«Не подключено» через UI Automation; сам индикатор не включать в tab order.
- Состояние должно различаться не только цветом: белая галочка обязательна для активного устройства.

### 4.7. Нижняя панель

- Слева допускается кнопка «Настройки», но в первой версии она может вести в небольшое меню с глобальным включением/выключением уведомлений.
- Справа — явная кнопка «Выход», полностью завершающая процесс и удаляющая tray-значок.
- Если отдельное окно настроек не реализуется, не оставлять неработающую кнопку-шестерёнку.

## 5. Иконки устройств

Шрифт с иконками использовать можно и желательно. Базовый вариант без сторонней runtime-зависимости — системный шрифт `Segoe Fluent Icons`, присутствующий в Windows 11. Сделать единый `DeviceIconResolver`, сопоставляющий свойства/класс устройства с glyph.

Минимальный набор типов:

- наушники/гарнитура;
- мышь;
- клавиатура;
- колонка/аудиоустройство;
- геймпад;
- телефон;
- перо;
- часы/носимое устройство;
- универсальная Bluetooth-иконка для неизвестного типа.

Не определять тип только по тексту имени. Сначала использовать доступные Windows device class/category/kind/container properties, затем безопасный fallback по имени, затем generic icon.

Если возможностей `Segoe Fluent Icons` недостаточно, разрешается подключить библиотеку или встроить open-source icon font, но только при соблюдении условий:

- библиотека совместима с WPF и .NET 10;
- лицензия допускает распространение и добавлена в `THIRD-PARTY-NOTICES.md`;
- в сборку включается только реально используемый ресурс или разумный по размеру пакет;
- не использовать web-font/CDN и не требовать интернет для отображения;
- не использовать библиотеку, которая тянет второй UI framework.

## 6. Bluetooth и заряд батареи

### 6.1. Обнаружение

- Использовать публичные Windows Runtime API из `Windows.Devices.Enumeration` и `Windows.Devices.Bluetooth` либо другой документированный Windows API, доступный desktop-приложению.
- Использовать `DeviceWatcher`/событийную модель для add/update/remove и изменения `IsConnected`, чтобы фоновые уведомления не зависели от секундного polling.
- Отдельно получать LE и Classic-представления и объединять их в доменную модель.
- Все WinRT/COM-объекты и подписки освобождать корректно при остановке и перезапуске watcher.
- События watcher могут приходить не с UI-потока; обновлять `ObservableCollection` только через Dispatcher.
- Обрабатывать выключение адаптера, отмену доступа, исчезновение устройства, `null` из `FromIdAsync`, таймаут и временный отказ без завершения процесса.

### 6.2. Батарея

- Основной документированный путь для BLE: стандартный GATT Battery Service `0x180F`, характеристика Battery Level `0x2A19`.
- Использовать `BluetoothCacheMode.Uncached` для явного обновления, когда это оправдано, но не инициировать бесконтрольное число соединений.
- Учитывать статус доступа GATT и проверять длину/диапазон значения. Валидный процент: 0–100.
- Подписка на уведомления характеристики допустима, если устройство её поддерживает; иначе чтение по расписанию.
- Для Classic/HID и устройств с нестандартным battery service показывать заряд только если он доступен через документированный Windows property/API или стандартный GATT-профиль.
- Не применять недокументированные реестровые ключи, reverse-engineered HID-команды или vendor-specific протоколы в первой версии.
- Отсутствие Battery Service является штатным состоянием, а не ошибкой устройства.
- Ограничить параллелизм чтения батарей (например, до 3–4 операций) и задать разумный timeout одной операции (ориентир 3–5 секунд).
- Секундный UI-цикл не обязан каждую секунду выполнять новый GATT read для каждого устройства. Он должен обновлять модель и запрашивать свежие данные с дедупликацией/кэшем, чтобы не разряжать устройства и не создавать connection storm. Для стабильных подключённых устройств допустим TTL батареи 10–30 секунд, а при ручном обновлении — принудительное чтение.

### 6.3. Модель состояния

Минимальные поля доменной модели:

```text
StableId
ContainerId
BluetoothAddress (если доступен)
DisplayName
DeviceKind
Transports (LE/Classic)
IsPaired
IsConnected
BatteryPercent (nullable)
BatteryUpdatedAt (nullable)
LastSeenAt
DataState (Fresh/Stale/Unavailable/Error)
```

## 7. Обновление данных

- При открытии панели: немедленный `RefreshAsync(forceBatteryRead: false)`, затем цикл с периодом 1 сек, пока окно видно.
- Кнопка refresh: `RefreshAsync(forceBatteryRead: true)`.
- Не допускать наложения циклов обновления: предыдущая операция должна быть переиспользована, отменена или пропущена через `SemaphoreSlim`/single-flight механизм.
- Закрытие панели отменяет её polling через `CancellationToken`, но не останавливает watcher подключений.
- Ошибка одного устройства не прерывает обновление остальных.
- Все исключения фоновых задач должны наблюдаться и логироваться.

## 8. Нативные уведомления Windows

- Использовать документированный механизм Windows App Notifications/toast notifications, совместимый с unpackaged desktop-приложением. До реализации проверить актуальную официальную документацию и выбрать стабильный вариант, совместимый с WPF и .NET 10.
- Если выбран Windows App SDK, не включать Windows App Runtime в publish-артефакт; явно описать внешний prerequisite и способ установки. Если можно реализовать корректные unpackaged toast notifications без этой зависимости, предпочесть более лёгкий вариант.
- Задать постоянный AppUserModelID, например `BluetoothNotify.App`.
- Если для корректного имени/иконки в центре уведомлений требуется Start Menu shortcut, manifest или регистрация activator, выполнить это в Inno Setup и полностью отменить при деинсталляции. Не оставлять ручную настройку пользователю.
- Уведомление отправлять только при подтверждённом переходе сопряжённого устройства из `Disconnected` в `Connected` после завершения начального snapshot.
- Защититься от дублей watcher: debounce одного устройства 3 секунды и не повторять уведомление, пока не был зафиксирован реальный переход обратно в disconnected.
- Текст: «{Имя устройства} подключено». Вторая строка: «Заряд: N%», только если заряд известен.
- Уведомления можно глобально выключить; значение сохраняется.
- Уведомления относятся ко всем сопряжённым устройствам; пользователь может отключить их только глобально в настройках приложения.
- Не требовать запуска от администратора.

## 9. Хранение настроек и журнал

- Настройки хранить в `%LocalAppData%\BluetoothNotify\settings.json`.
- Сохранять как минимум:
  - глобальное включение уведомлений;
  - версию схемы настроек.
- Не хранить пользовательское состояние подключения и не сохранять значение круглого индикатора: после запуска оно заново определяется по данным Windows.
- Запись выполнять атомарно через временный файл и замену, чтобы сбой не портил JSON.
- Не хранить адреса устройств или другие идентификаторы в логах без необходимости; при диагностике маскировать Bluetooth-адрес.
- Логи писать в `%LocalAppData%\BluetoothNotify\logs`, с ограничением размера/числа файлов. Уровень по умолчанию — Information, без высокочастотной записи каждую секунду.

## 10. Рекомендуемая архитектура

Придерживаться MVVM и отделить платформенную работу от UI.

```text
BluetoothNotify.App
  App / startup / single-instance
  Views
    TrayPanelWindow
  ViewModels
    TrayPanelViewModel
    BluetoothDeviceViewModel
  Models
    BluetoothDeviceState
  Services
    TrayIconService
    BluetoothDeviceMonitor
    BatteryReader
    NotificationService
    SettingsStore
    DeviceIconResolver
    PanelPlacementService
  Interop
    Shell_NotifyIcon / Shell_NotifyIconGetRect
    DWM helpers

BluetoothNotify.Tests
```

Ожидаемые интерфейсы: `IBluetoothDeviceMonitor`, `IBatteryReader`, `INotificationService`, `ISettingsStore`, `ITrayIconService`, `IDeviceIconResolver`.

Допускается `CommunityToolkit.Mvvm`. Не добавлять крупный UI framework только ради одного контрола. Все версии пакетов должны быть актуальными стабильными, совместимыми с .NET 10, и закреплёнными централизованно. Перед выбором пакета проверить официальный источник, статус поддержки и лицензию.

### Tray interop

Для точного hover-поведения и позиционирования предпочтительно реализовать tray icon через документированные Win32 API `Shell_NotifyIcon` и `Shell_NotifyIconGetRect`, сохраняя собственные `HWND` и `uID`. Обязательно:

- восстановить иконку после перезапуска Explorer через сообщение `TaskbarCreated`;
- удалить иконку при штатном выходе;
- использовать версию notification icon API, поддерживающую современное поведение;
- не полагаться на фиксированные координаты панели задач.

Использование `System.Windows.Forms.NotifyIcon` допустимо только если агент докажет, что может надёжно получить bounds значка, реализовать hover-delay и восстановление после Explorer restart без reflection и хрупких hacks.

## 11. Установщик Inno Setup

- Добавить в репозиторий исходный скрипт Inno Setup, например `installer/BluetoothNotify.iss`.
- Установщик собирается из framework-dependent Release publish для `win-x64` и не содержит .NET Desktop Runtime, Windows App Runtime или другие framework runtimes.
- Установка первой версии — per-user в `{localappdata}\Programs\Bluetooth Notify` с `PrivilegesRequired=lowest`; создать запись в «Установленные приложения» Windows и корректный деинсталлятор.
- Создать ярлык в меню «Пуск». Если механизму нативных уведомлений нужны постоянный AppUserModelID, shortcut properties, manifest или COM-регистрация, выполнить это воспроизводимо средствами Inno Setup/вспомогательного шага установки и полностью удалить при деинсталляции.
- Перед установкой проверить наличие совместимого .NET Desktop Runtime 10 x64. Если его нет, показать понятное сообщение и предложить открыть официальную страницу загрузки; не загружать и не устанавливать runtime скрытно.
- Если выбран Windows App SDK как внешний framework prerequisite, аналогично проверить его наличие и сообщить пользователю точное требование. Не включать его runtime в установщик.
- Не запрашивать права администратора. Все необходимые ярлыки и регистрации выполнять в области текущего пользователя.
- При обновлении корректно закрыть запущенный экземпляр либо попросить пользователя закрыть приложение; не оставлять частично заменённые файлы.
- При удалении завершить приложение, убрать tray-значок, ярлыки и регистрацию уведомлений. Пользовательский `settings.json` и логи удалять только если пользователь явно выбрал соответствующую опцию деинсталлятора.
- Версия приложения и установщика должна задаваться из одного источника либо передаваться в `.iss` из build-скрипта, чтобы версии не расходились.
- Добавить документированную команду сборки installer через Inno Setup Compiler (`ISCC.exe`) после `dotnet publish`.

## 12. Публикация без runtime

Проект должен явно содержать framework-dependent настройки:

```xml
<TargetFramework>net10.0-windows</TargetFramework>
<UseWPF>true</UseWPF>
<OutputType>WinExe</OutputType>
<SelfContained>false</SelfContained>
<PublishSingleFile>false</PublishSingleFile>
<PublishTrimmed>false</PublishTrimmed>
```

Команда публикации для первой версии:

```powershell
dotnet publish .\src\BluetoothNotify.App\BluetoothNotify.App.csproj -c Release -r win-x64 --self-contained false
```

Требования к артефакту:

- не содержит .NET runtime/runtime packs;
- запускается на чистой поддерживаемой Windows после установки .NET Desktop Runtime 10 x64 и других явно заявленных framework prerequisites;
- при отсутствии .NET runtime показывает стандартное понятное предложение установить его, а не падает без сообщения;
- README содержит точный список prerequisites, команды build/test/publish и путь к результату;
- не обещать «один exe»: framework-dependent WPF-приложение может состоять из `.exe`, `.dll`, `.deps.json`, `.runtimeconfig.json` и библиотек приложения.

Если используется Windows App SDK, отдельно проверить и задокументировать его deployment mode. Нельзя незаметно превратить публикацию в self-contained только ради уведомлений.

## 13. Надёжность и производительность

- Запуск до появления tray-значка: ориентир не более 2 секунд на обычном ПК; Bluetooth enumeration продолжать асинхронно.
- UI должен оставаться отзывчивым во время сканирования и GATT-запросов.
- В покое не выполнять секундный polling и не держать активные GATT-соединения без необходимости.
- Целевой idle CPU при скрытой панели — практически 0%; рост памяти со временем отсутствует.
- Обработать suspend/resume, смену пользователя/сессии и перезапуск Explorer настолько, насколько это доступно desktop-приложению.
- При завершении отменить задачи, отписаться от событий, освободить WinRT/GATT-ресурсы и удалить значок.
- Глобальные обработчики `DispatcherUnhandledException`, `AppDomain.UnhandledException` и `UnobservedTaskException` могут вести лог, но не должны скрывать программные ошибки без причины.

## 14. Тесты

### Автоматические

- объединение LE и Classic представлений одной физической периферии;
- устойчивость `StableId` и обновление состояния без создания дублей;
- сортировка устройств;
- сопоставление device kind → icon;
- цветовые пороги батареи и `null` как «недоступно»;
- state machine подключения, отсутствие уведомлений на initial snapshot и дедупликация;
- отмена/дедупликация refresh;
- чтение, миграция и восстановление повреждённых настроек;
- позиционирование панели на разных work area/DPI — для чистой вычислительной части.

### Ручная проверка

Проверить минимум с BLE-мышью/клавиатурой, аудиоустройством Classic+LE, устройством без доступного заряда и при выключенном Bluetooth-адаптере.

Матрица:

- hover, click, outside click, `Esc`, контекстное меню;
- taskbar на каждой стороне экрана;
- два монитора с разным DPI;
- Explorer restart;
- подключение/отключение и отсутствие дублей toast;
- ручное обновление при уже выполняющемся автообновлении;
- 0, 1 и много устройств;
- повреждённый `settings.json`;
- запуск без сети;
- запуск framework-dependent publish на машине только с заявленными prerequisites.
- установка, обновление и удаление через Inno Setup;
- поведение установщика при отсутствии .NET Desktop Runtime 10 x64;
- отсутствие .NET runtime в составе installer.

## 15. Критерии приёмки

Работа считается выполненной, если:

1. `dotnet build -c Release` и `dotnet test -c Release` проходят без ошибок.
2. После запуска есть ровно один процесс и один tray-значок, обычное окно и console window не появляются.
3. Панель открывается наведением и кликом, корректно расположена возле значка и не мерцает.
4. Панель показывает все сопряжённые устройства без дублей LE/Classic, состояние подключения, тип и заряд там, где устройство его реально сообщает.
5. Неизвестный заряд показан как недоступный, а не как 0%.
6. Круглый индикатор автоматически показывает фактическое состояние: зелёный с белой галочкой только для сопряжённого активного устройства, тёмный без галочки для неактивного. Пользователь не может изменить его вручную.
7. Автообновление выполняется раз в секунду только при открытой панели; ручная кнопка инициирует принудительный refresh без зависания и параллельных штормов.
8. Нативное уведомление появляется один раз на реальное подключение сопряжённого устройства и не появляется при initial snapshot.
9. Приложение не падает при выключенном адаптере, недоступном GATT, неподдерживаемой батарее, перезапуске Explorer или исчезновении устройства.
10. Release publish является framework-dependent и не включает .NET runtime.
11. README позволяет другому разработчику собрать, протестировать, опубликовать и установить prerequisites без догадок.
12. Inno Setup installer устанавливает и удаляет приложение, настраивает нативные уведомления, проверяет внешний .NET Desktop Runtime 10 x64 и сам не содержит runtime.
